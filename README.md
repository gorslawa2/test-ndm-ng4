
# Nginx Proxy Chain & XFF Security Lab

Тестовое задание на позицию DevOps Engineer. Реализация защищённой цепочки обратных прокси с корректной передачей заголовка `X-Forwarded-For`.

## Суть решения
Стенд развёрнут в Docker/Podman и состоит из **трёх независимых экземпляров Nginx** (порты 8081, 8082, 8083) и приложения `traefik/whoami`. 

Каждый порт — это отдельный входной шлюз. Запрос может прийти на любой из них и пройти через произвольную цепочку серверов перед попаданием в приложение.
<br/>
***Chain*** формируется простым набором цифр от одного до трёх. (8081/hop/23 формирует цепочку `nginx1 -> nginx2 -> nginx3 -> whoami`).



### Защита от спуфинга (Ключевая часть)
Приложение никогда не получает поддельные IP. В конфигурации Nginx используется механизм доверенных сетей (`geo` + `map`):
*   Если запрос пришёл из внутренней сети контейнеров — мы доверяем накопленному `X-Forwarded-For` и добавляем текущий сервер.
*   Если запрос пришёл извне — мы **полностью игнорируем** пользовательский заголовок `X-Forwarded-For` и начинаем цепочку с реального IP клиента (`$remote_addr`).

## Протокол тестирования
Все проверки выполнялись удалённо. Замените `test.z17.ru` на IP хоста, если тестируете на другой машине.

| Сценарий | Команда curl | Ожидаемый результат | Статус |
| :--- | :--- | :--- | :--- |
| **Прямой запрос** | `curl -s http://test.z17.ru:8081/api \| jq .headers` | Цепочка: `[Client_IP, 10.89.0.11]` | ✅ PASS |
| **Цепочка 3 ноды** | `curl -s http://test.z17.ru:8081/hop/23 \| jq .headers` | Цепочка: `[Client_IP, .11, .12, .13]` | ✅ PASS |
| **Защита от подмены** | `curl -s -H "X-Forwarded-For: 99.99.99.99" http://test.z17.ru:8081/api \| jq .headers` | Фейковый IP отброшен, виден только реальный клиент | ✅ PASS |
| **Вход через Nginx 2** | `curl -s http://test.z17.ru:8082/hop/13 \| jq .headers` | Цепочка начинается с `.12`, затем `.11`, `.13` | ✅ PASS |
